# What the site sync manages

Almost everything on this wiki is hand-written. No script touches it.
Edit those pages freely — including
[which fork, and why](../getting-started/comparison.md).

The exceptions are the files in this table. They are generated by a
script in the site repo (`scripts/sync-wiki.mjs`, run as
`npm run sync:wiki`). A hand edit inside them is overwritten the next
time the script runs.

| Generated file | Generated from | Edit this instead |
| --- | --- | --- |
| `releases/changelog.md` | site repo: `src/data/changelog.js` | that data file |
| `assets/steering-torque.svg` | site repo: `src/data/chart-geometry.js` | that data file |
| `assets/steering-torque-data.js` | site repo: `src/data/chart-geometry.js` | that data file |
| `technical/route-library.md` | the pages under `technical/` | those pages |
| `assets/js/car-checker-data.js` | [supported cars](../getting-started/supported-cars.md) | that table |

Generated files say so: each one carries a "Generated … do not edit"
comment at the top.

## Two directions of travel

Sync is not one-way. [supported cars](../getting-started/supported-cars.md)
is a source, not a generated file: the script reads its first table and
updates the site from it. Edit that table freely. (Only the first
table is read; the rest of the page is untouched.)

## The safety net

The sync records a fingerprint of every generated file after each run.
If a generated file was edited by hand since the last sync, the next
run **stops** and names the file, instead of overwriting your work.
Nothing is lost silently.

To overwrite a hand edit on purpose, run this from the site repo:

```
npm run sync:wiki -- --force
```

One part of one generated file stays hand-written:
`releases/changelog.md` keeps everything below its
`## Upstream release notes` heading word for word. The sync never
rewrites that tail and never stops for edits to it.

The site repo has one generated file of its own,
`src/data/supported-cars.json` — the same rule applies to it.

## When a release lands

The maintainer publishes release notes on
[zoompilot.ai](https://zoompilot.ai/release-notes). No repo carries
them, so a person transcribes them first:

1. Add the release to the site repo's `src/data/changelog.js`.
   Copy the notes as published. Keep the year-claim wording this
   wiki already uses where the site words it differently.
2. Run `npm run sync:wiki` from the site repo.
3. Commit and push both repos. The wiki push deploys the site.

A daily check (`drift-check.yml` in this repo) watches both ends.
It compares the current release on zoompilot.ai with the newest
version on [the changelog](../releases/changelog.md). It also polls
`docs/zoompilot` on the zoompilot repo, which
[the technical notes](../technical/index.md) mirror by hand. When
either moves first, it opens one issue named "Wiki drift: ...".
The issue carries this runbook. A clear run closes it.
